Socket listeners attached AFTER socket connects (race condition)\n2. Connection errors hidden, components think they're connected when not\n3. Message filtering logic reversed (filters OUT what should be received)\n4. Socket connection state not exposed to components\n5. Socket join event not triggered on fast connections\n6. Multiple socket instances created, out of sync\n7. Peer socket IDs never sent to clients (WebRTC blocker)\n8. Participant updates didn't include socket IDs\n9. Components emit events without validating connection\n10. Error handling swallows failures with false \"success\" status\n\n### The Solution\n✅ **All 10 issues fixed**, builds pass, ready for testing\n\n---\n\n## DETAILED FINDINGS\n\n### Issue #1: CRITICAL - Socket Listener Race Condition\n\n**Severity**: 🔴 BLOCKER  \n**Impact**: All real-time events lost\n\n**Location**: `client/src/features/presence/useRoomPresence.ts` lines 48-71\n\n**Problem**:\n- Socket created with `autoConnect: false`\n- Socket instance set in React state → triggers re-render  \n- Socket connects\n- But component's useEffect that attaches listeners hasn't run yet\n- Server sends events while listeners not registered\n- Events are lost\n\n**Timeline of Failure**:\n```\n1. socket = createPresenceSocket()      \n2. setSocketInstance(socket)             ← State update triggers re-render\n3. socket.connect()                      ← Socket connects (very fast, <1ms)\n4. 'connect' event fires on server\n5. ❌ Client's useEffect runs AFTER event is lost\n```\n\n**Fix Applied**: \n✅ Listeners attached in hook BEFORE socket.connect() is called\n\n---\n\n### Issue #2: CRITICAL - Connection Errors Hidden  \n\n**Severity**: 🔴 BLOCKER  \n**Impact**: Silent failures, no error visibility\n\n**Location**: `client/src/features/presence/useRoomPresence.ts` lines 77-84\n\n**Broken Code**:\n```typescript\nsocket.on('connect_error', (err) => {\n  setState((current) => ({\n    ...current,\n    status: 'joined',    // 🔴 LIES\n    error: null,         // 🔴 LIES\n  }))\n})\n```\n\n**Problem**: \n- Connection fails\n- Component state says \"joined\" (false)\n- Components emit events thinking connected (but they're not)\n- Events silently fail\n- No error to investigate\n\n**Fix Applied**:\n✅ Report actual error, set `isConnected: false`, add proper error message\n\n---\n\n### Issue #3: CRITICAL - Message Filter Logic Backwards\n\n**Severity**: 🔴 BLOCKER  \n**Impact**: Messages one-way only, teacher sees student but not vice versa\n\n**Location**: \n- `client/src/features/classroom/components/TeacherClassroomView.tsx` line 66\n- `client/src/features/classroom/components/StudentClassroomView.tsx` line 52\n\n**Broken Code**:\n```typescript\nconst handleChatMessage = (msg: ChatMessage) => {\n  if (msg.senderId !== user?.uid) {  // 🔴 BACKWARDS LOGIC\n    sendMessage(msg)  \n  }\n}\n```\n\n**The Logic Error**:\n- Student (UID=456) sends to Teacher (UID=123)\n- Teacher receives `chat:message` with `msg.senderId=456`\n- Check: `456 !== 123` = TRUE → Stored ✓\n- Teacher sends to Student  \n- Teacher receives their message echoed back with `msg.senderId=123`\n- Check: `123 !== 123` = FALSE → **NOT STORED** ✗\n- Result: Teacher sees student messages but student sees nothing from teacher\n\n**Fix Applied**:\n✅ Changed logic: skip only if message is from SELF, accept all others\n\n---\n\n### Issue #4: HIGH - Socket Connection State Not Exposed\n\n**Severity**: 🟠 HIGH  \n**Impact**: Components emit events without checking if connected\n\n**Location**: `client/src/features/presence/useRoomPresence.ts`\n\n**Problem**:\n- Only had 4 status values: `'idle' | 'connecting' | 'joined' | 'error'`\n- No way to know if socket exists but disconnected\n- Components checked `if (presence.socket)` but didn't check if actually connected\n- Could emit events to dead socket\n\n**Fix Applied**:\n✅ Added `isConnected: boolean` field + `'disconnected'` status  \n✅ Components now check `if (!socket || !presence.isConnected) return`\n\n---\n\n### Issue #5: CRITICAL - Socket Join Not Triggered\n\n**Severity**: 🔴 BLOCKER  \n**Impact**: User not added to room, no participant updates\n\n**Location**: `client/src/features/presence/useRoomPresence.ts` lines 59-71\n\n**Problem**:\n```typescript\nconst join = () => { socket.emit('presence:join', ...) }\nsocket.on('connect', join)  // 🔴 Listener attached...\nsocket.connect()             // 🔴 Then connect\n```\n\nIf socket connects BEFORE listener attached:\n- 'connect' event fires\n- Listener not registered yet  \n- Join never emitted\n- User not added to room\n\n**Fix Applied**:\n✅ Attach listener BEFORE socket.connect()\n✅ Added `joinAttempted` tracking for reconnections\n\n---\n\n### Issue #6: HIGH - Socket Instances Created Multiple Times\n\n**Severity**: 🟠 HIGH  \n**Impact**: Out-of-sync state, message loss across hooks\n\n**Location**: `client/src/features/presence/presence.socket.ts`\n\n**Problem**:\n- No singleton pattern\n- Each call to `createPresenceSocket()` made new instance\n- Multiple hooks = multiple sockets\n- Different event listeners on each\n- Chaos\n\n**Fix Applied**:\n✅ Implemented singleton pattern with global socket  \n✅ Returns existing socket if connected\n✅ Only one socket instance for entire app\n\n---\n\n### Issue #7: HIGH (WebRTC Blocker) - Peer Socket IDs Not Sent\n\n**Severity**: 🟠 HIGH  \n**Impact**: WebRTC can't target specific peers\n\n**Location**: `server/src/presence/presence.gateway.ts` lines 73-77\n\n**Problem**:\n```typescript\nconst participants = registry.join(roomCode, participant, socket.id)\n// Server knows socket.id but doesn't send it\nacknowledge({ ok: true, participants })  \n// 🔴 participants = {userId, displayName, role} -
